## 深度复核后的框架修复（基线 e2c33d9）

- 所有显式线程池统一按每次提交复制调用上下文；覆盖 Skill 自动连接、网络巡检、工作流、子 Agent、记忆写入、地点解析和批量天气。并行调用不再丢失用户身份，复用线程不继承前一请求的上下文。
- 设备、区域、连接、Skill 的相关变更共用按用户/工作区隔离的文件锁；网络 IO 在锁外执行。连接配置版本与测试标识分离，迟到的测试不能复活删除记录、覆盖新配置或新状态。
- 同一配置上较早完成的有效读取证据仍返回原调用方，不因另一次并发测试而被判定为工具失败；只是停止回写已被更新的连接状态。
- 查询连接、读取 Skill 不再执行去重或删除。启动维护显式迁移旧重复连接，重绑 Skill 引用，保留仍被引用的共享凭据；重复执行无副作用。
- 编辑连接不能变更成另一条已存在的端点；已删除连接的过期编辑请求不会重新创建记录。认证配置校验失败时不先修改凭据。
- 删除旧资产写入/探测、内存线程巡检、退役计划调度、旧基线写入/比较和旧概览入口。旧任务的恢复、重试、证据索引和历史基线读取保留。
- 删除只有旧测试调用的天气包装、单模型路由包装和软删除函数；测试改用正式工具注册表、模型候选列表和永久删除入口。硬删除产品语义不变。
- 网络测试改走正式连接和持久任务 Worker，新增独立回归覆盖身份隔离、线程复用、六类连接竞态、凭据保护、纯读取、显式迁移及历史任务重试。
- 实测六个 Telnet 端口时，首轮两项未检测到提示符，独立读取确认设备返回合法提示符且后续六项均通过。核查另确认接收循环把单次 socket 超时当作整体截止：现改为在剩余握手预算内继续接收、限制单次等待不越过截止时间，并缩短等待静默控制台的被动阶段。此后六端口并行连接均成功，约 1 秒；未宣称已证明首轮失败的唯一原因。
